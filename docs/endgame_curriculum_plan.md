# Plan: End-game curriculum fine-tuning of the PPO agent

## Context
The deployed PPO agent (`models/ppo_best.zip`) beats the Q-agent ~70%, but close end-games (both
players near 200) are rare in training, so it may play them poorly. Hypothesis: fine-tuning from
`ppo_best.zip` with a share of episodes that *start* in close end-game positions improves play
in those positions, and therefore win rate.

The experiment isolates **one variable — start-state distribution**. A newly trained control arm
gets the identical fine-tune (same opponents, steps, hyperparams, reward, evaluation) with normal
0–0 starts only, so any curriculum-vs-control difference is attributable to the curriculum.
`ppo_best` is the shared starting point ("step 0") and a reference, not the control.
Observation space stays 43-dim and the reward is unchanged → webapp unchanged if it wins.

## Fixed definitions
- **Close end-game position**: the moment before `start_round()` (hands empty) where both total
  scores are in [150, 199] and |difference| ≤ 40. (Positions with any score ≥ 200 — e.g. a tie
  above 200 that continues, `game.py:148-149` — are excluded; they're outside the training
  sampler's range.)
- **Minimum detectable effect (MDE)**: 3 pp on the primary metric P2 (win rate from real close
  end-game positions). Rationale: the curriculum targets these positions directly, so an effect
  should be concentrated there. **Implied full-game effect** = 3 pp × `f_close`, where `f_close`
  = fraction of games that reach a close end-game position (measured in Step 0) — e.g. ~1–1.5 pp
  if `f_close` ≈ 0.4. The experiment is designed to detect end-game improvement; a full-game
  improvement is claimed only if P1 is itself significant (see criteria).
- **Held-out opponents** (never trained against): `ThresholdAgent` (new, below) and `ppo_final`
  (loaded with stats from `models/vec_normalize_final.pkl` via `_load_obs_rms`; caveat: it was
  trained against an opponent fed unnormalized obs, `train_ppo.py:146`, so it's an unusual policy).
- **Training opponents** (identical in both arms, sampled per episode): 70% frozen `ppo_best`,
  30% Q-agent. Both are deterministic (`ppo_agent.py:60`, `q_agent.py:89` epsilon=0), so
  head-to-head vs `ppo_best` partly measures exploitation and is secondary only.
- **Dependencies**: SB3 is pinned at 2.4.1 in `uv.lock`; all SB3 behaviour below assumes that.

## Step 0 — Calibration, headroom, position capture (no training; go/no-go gate)
Order matters; `evaluate_endgame.py --headroom` runs these in sequence:
1. **Calibrate ThresholdAgent first** (calibration seeds 0–999, 1,000 seeds × 2 seats vs
   ppo_best). Target ppo_best win rate 55–85%. If outside, tune the single `aggression`
   parameter until inside, then **freeze it**. Everything below uses the frozen agent.
2. **Capture games** (disjoint seeds 100000+): 2,500 seeds × 2 seats of ppo_best vs frozen
   ThresholdAgent, via a custom round loop (`Game.play_game` has no per-round hook). At every
   close end-game position, before `start_round()`, record: both scores, round parity, which seat
   ppo_best occupies, a copy of `deck._cards` (order matters) and `game.rng.getstate()` (the deck
   shares `Game.rng`, `game.py:31`, which drives reshuffles, `deck.py:33`; restore with
   `game.rng.setstate()`, never by replacing the rng object). Also measure `f_close`.
   **Burn distribution**: from a *separate* set of 1,000 ppo_best-vs-ThresholdAgent games
   (seeds 200000+), record deck size at close end-game positions → used only for the training
   burn, so training never sees statistics of the eval positions.
3. **Headroom bound** (vs ThresholdAgent, counted per ppo_best game, seat-agnostic) = fraction of
   ppo_best's games that reach ≥1 close end-game position and that ppo_best then loses, × 0.3
   (optimistic share a better end-game policy could flip). Also report the raw fraction.
4. **Score-awareness** (informational only): on matched hand states (same hand, same deck-size
   bucket), ppo_best's draw rate trailing-near-200 minus leading-near-200.
5. **Go/no-go** (both sides in full-game units): stop and report if headroom bound
   < 2 × (3 pp × `f_close`), i.e. even the optimistic ceiling can't comfortably cover the MDE's
   full-game equivalent.
6. **Real-position suite**: from each captured game, take **one uniformly random** close position
   (not the first, which would over-sample scores just past 150). Stratify by the leader's score
   band (150–174, 175–189, 190–199) and sample equally per band, ≤ 2,000 total, fixed RNG →
   `results/endgame_positions.pkl`. Not generated by the training sampler.

## Experimental design
- **Arms** (both fine-tuned from `ppo_best.zip`, reward unchanged):
  - **control**: `scenario_prob = 0.0`
  - **curriculum**: `scenario_prob` calibrated so **~30% of training steps** come from scenario
    starts (scenario episodes are short, so this needs well above 30% of episodes). Calibrate
    with a rollout-only measurement (no learning) before the pilot; then fix the value.
- **Hyperparams**: everything as `train_stage1` except `learning_rate=3e-5` (via
  `custom_objects={"learning_rate": 3e-5}`; SB3 2.4.1 rebuilds the schedule from it; Adam state
  restored from the zip). `ent_coef` stays 0.01. `learn(total_timesteps=500_000)` (runs
  507,904 steps = whole rollouts of 4×2048; report actual).
- **Frozen normalization**: `VecNormalize(norm_obs=True, norm_reward=False, training=False)` and
  **explicitly** set `env.obs_rms = _load_obs_rms("models/baseline/ppo_best_vecnorm.pkl")`
  (a fresh VecNormalize starts at mean 0 / var 1). `normalize_stats.json` stays valid.
- **Seeding**: for run seed `s`, call `model.set_random_seed(s * 1000)` after `set_env`, and
  nothing else. SB3's `set_random_seed` seeds torch/numpy/random **and** calls `env.seed(...)`,
  which queues seeds `s*1000 + i` for the next reset (separately chosen env seeds would be
  silently overridden; ×1000 keeps env streams of different runs disjoint). Opponent-pool and
  scenario sampling drawn from `self.np_random`.
- **Model safety**: copy `models/ppo_best*`, `models/ppo_final.zip`, `models/vec_normalize_final.pkl`,
  `models/q_table.pkl` to `models/baseline/` at start and load only from there; never write to
  `models/ppo_best*`/`models/ppo_final*`. Outputs go to `models/ft/{arm}_s{seed}/`:
  `CheckpointCallback(save_freq=100_000 // n_envs)` + `final.zip`. Monitoring
  `WinRateCallback(save_best=False, eval_freq=50_000 // n_envs)` for TensorBoard only.
- **Evaluated checkpoint**: `final.zip` of every run (no best-of-N selection); step-0 `ppo_best`
  evaluated identically.
- **Pilot (two gates)**: 5 control + 2 curriculum seeds. Measure time per run, seed-to-seed SD of
  P2 and P1, and control vs step 0.
  - **Degradation gate**: if control's mean P1 is below step 0 by > 2 pp, fine-tuning itself is
    harmful in this setup → stop and report.
  - **Sizing**: per-run variance = between-seed variance + binomial eval noise. Size seeds per arm
    for 80% power at the 3 pp MDE on P2 (two-sided α = 0.05, Welch), using the **upper 80%
    confidence bound** of the pilot SD. Also compute, and report, the power of P1 at the implied
    full-game effect for that n (expected to be low; stated up front). **If required n > 20 per
    arm, stop and report options to the user.** Same seed list across arms; pilot runs count
    toward their arms.
- Report the share of training **steps** coming from scenario starts.

## Metrics & success criteria (pre-registered)
Units of analysis = **runs** (per-run win rate, then mean/CI across runs), never pooled games.
- **Primary — P2**: win rate vs frozen `ThresholdAgent` from the real-position suite. Each saved
  position is restored as a `Game` (scores, parity, deck order, rng state) and played to the end
  with `Game.play_game` (it already handles first-mover alternation each round), **twice**:
  candidate in seat 0, then in seat 1. Scores and the deal order stay with the **seats** (so card
  dealing to `players[0]` first, `game.py:51-53`, is unchanged); the candidate therefore takes
  that seat's score. Each playthrough is labelled by type **from the candidate's perspective**
  (trailing / leading / close-tied) and by score band. Reported overall, by type and by band.
- **Key secondary — P1**: full-game win rate vs `ThresholdAgent`, 2,500 common seeds × 2 seats.
  Reported as a two-sided superiority test with its (low) power stated.
- **Other secondary**: real-position suite vs ppo_best; per-type draw/bust rates; head-to-head vs
  `ppo_best` (exploitation caveat) and vs `ppo_final` (held out).
- **"No harm" checks** (P1, and vs Q-agent and Random), all **curriculum vs control** on per-run
  means (step 0 shown for context only — `ppo_best` was the max over many noisy evals, so any
  fine-tune may regress vs it): pass iff the point estimate of (curriculum − control) ≥ −1 pp
  **and** curriculum is not significantly worse (one-sided Welch p ≥ 0.05). Deliberately a
  "no evidence of harm" check, not a formal non-inferiority test, because the latter would need
  far more seeds than P2 sizing gives.
- **Success requires all**: (1) curriculum > control on P2, Welch p < 0.05 on per-run means
  (permutation test as confirmation); (2) all "no harm" checks pass.
- **Conclusions**: success ⇒ "curriculum improves end-game play without detectable harm".
  "Curriculum wins more games" is claimed only if P1 is also significant.
- Always report control vs step 0 and curriculum vs step 0 on P1 and P2.
- If successful: follow-up dose check at half the scenario step share.

## Implementation

### 1. `flip7/environments/gym_env.py`
- New optional ctor args (defaults reproduce current behaviour exactly):
  `opponent_pool: list[tuple[Agent, float]] | None`, `scenario_prob: float = 0.0`,
  `scenario_sampler: Callable | None = None`.
- `reset` (`gym_env.py:137-142`): create `Game(seed)`; pick opponent; with prob `scenario_prob`
  apply the scenario **before** `_ensure_player_turn()` (`gym_env.py:116-135`): set both
  `total_score`s, `game.deck.burn(k)`, set `game.round_number = first_parity` (0 → agent first,
  1 → opponent first; read as `round_number % 2` before `start_round()` increments it; stays small
  so the `> 50` truncation is unaffected). Then `_ensure_player_turn()`.
- `flip7/engine/deck.py`: add `Deck.burn(k)` (pop k cards).

### 2. `flip7/engine/snapshot.py` (new)
- `capture(game) -> dict` and `restore(d) -> Game` for pre-`start_round()` positions (scores,
  `round_number`, `current_player_idx`, deck card list, `rng.getstate()`). Used by Step 0 and P2;
  no env involvement, so seats are placed exactly as recorded.

### 3. `flip7/agents/threshold_agent.py` (new)
- p(bust) and E[card|safe] from `game.deck.card_counts()`; if the deck is empty, use the
  post-reshuffle distribution (full deck minus cards in play, mirroring `Deck.reshuffle`).
- Base rule: DRAW iff (1−p)·E[card|safe] − p·hand_sum > −aggression·f(score gap), where the
  aggression term is non-zero only when trailing and the leader is ≥ 150.
- Overrides, checked **in this order** (first match wins):
  1. Opponent done (stayed/busted) and staying now wins the game (my total + hand ≥ 200 and >
     their final total) → STAY (respects the both-over-200 rule, `game.py:102-115`).
  2. Opponent done and staying now loses the game (their final total ≥ 200 and > my total +
     hand) → DRAW.
  3. Opponent not done, staying gives me ≥ 200, and their total + current hand < my total +
     hand → STAY.
  4. Otherwise the base rule.

### 4. `flip7/training/curriculum.py` (new)
- `sample_endgame_scenario(rng)`: uniform over types, every score clamped ≤ 199
  (`game.py:98-115` only checks for a winner at round end; obs clamps at 1.0):
  `both_close` both ∈ [160,199]; `trailing` me ∈ [110,170], opp ∈ [175,199]; `leading`
  mirrored; `tied` me ∈ [150,199], opp = clamp(me ± [0,5], ≤ 199); `first_parity` ∈ {0,1};
  `burn` k sampled from the Step 0 deck-size distribution (k = 78 − deck size, ≤ 77).
  Training deliberately includes wider gaps (up to ~89) than the "close" eval definition (≤ 40)
  to cover desperate/comfortable near-200 states; P2 by type shows where effects land.
- `build_frozen_ppo(model_path, vecnorm_path) -> PPOAgent`: `PPOAgent(model, {"mean","var"})`
  from `_load_obs_rms` (as `evaluate_model`, `train_ppo.py:227-232`); `PPOAgent.load` only
  accepts JSON stats.
- `finetune(arm, seed, steps=500_000)` per the design above.
- CLI: `uv run python -m flip7.training.curriculum --arm {control,curriculum} --seed N [--steps N]`.

### 5. `flip7/training/evaluate_endgame.py` (new)
- `paired_eval(a, b, seeds)`: each seed played twice with seats swapped; stochastic agents
  (Random) get an RNG seeded from the game seed so pairs are truly paired. Refactor `_run_eval`
  (`train_ppo.py:182`) to return results (keep prints).
- Modes: `--headroom` (Step 0), `--calibrate-scenario`, `--pilot`, `--full`. Capture uses a
  custom round loop; P2 uses `snapshot.restore` + `Game.play_game` with agents in seat order.
- Stats: per-run win rates; Welch t-test + permutation test; run-level 95% CIs.
- Writes `results/endgame_headroom.md` and `results/endgame_ablation.md`.

### 6. Tests (`tests/test_env_scenarios.py`, `tests/test_snapshot.py`, `tests/test_threshold_agent.py`)
- Defaults → identical obs/rewards to the current env for a fixed seed.
- Scenario reset: scores ≤ 199; deck counts + cards in hands = 78 − burned (k < 76); k = 77
  reshuffles cleanly; first actor matches `first_parity`; opponent-first acts with scenario scores.
- Fine-tune setup: `model.lr_schedule(1.0) == 3e-5`; `env.normalize_obs(x)` equals
  `PPOAgent._normalize_obs(x)`; `env.obs_rms` unchanged after a short `learn`.
- Seeding: same run seed → identical first rollout; different seeds → different.
- Snapshot: capture → restore reproduces identical subsequent play (same cards to the same
  seats, same outcome) for deterministic agents.
- `ThresholdAgent`: empty-deck safe; override order (lead 190–100, opp stayed on 25, I hold 15 →
  STAY); both-over-200 handling.
- Training never writes to `models/ppo_best*` / `models/ppo_final*`.

## Out of scope
- No observation features, reward changes, or webapp changes.
- Deployment only if successful: re-export with `export_onnx`, fixing it to read stats via
  `_load_obs_rms` (`VecNormalize.load` fails on the custom dict, `export_onnx.py:67`).
- ThresholdAgent is calibrated against `ppo_best` only; its difficulty vs fine-tuned models may
  differ (acceptable — it's a fixed yardstick for both arms).
